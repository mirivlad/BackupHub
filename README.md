# BackupHub

**BackupHub** — свободная self-hosted система резервного копирования и восстановления. Лицензия GNU GPL-3.0-only.

## 0.1.0 Preview 1

**Это устанавливаемая предварительная версия, не production-ready система.** Она позволяет попробовать основные файловые сценарии и восстановить собственные данные, но пока **не заменяет проверенную независимую резервную копию** критичных серверов.

Доступные типы источников:
- локальный каталог Linux (содержимое и базовые файловые метаданные);
- SMB2/3 (учётная запись, общая папка, подпапка; SMB1 не поддерживается);
- SSH/SFTP (пароль и проверка host key через `/etc/backuphub/known_hosts`);
- **обычный PostgreSQL** — логический `pg_dump -Fc` с проверкой TOC через `pg_restore -l`. **Специальный PostgreSQL Pro 1C с крупным `public.config` пока не поддерживается.**

Реализованы: ручной запуск, интервальное расписание, журнал выполнений и отказов, зашифрованные Restic-снимки файловых деревьев, история по датам, просмотр файлов, экспорт одного файла или выбранных папок и файлов в ZIP, безопасное восстановление в **новый** каталог на сервере. Web UI на русском, авторизация и аудит; один автономный экземпляр на площадку.

**Ограничения:** удалённые деревья SMB/SFTP временно целиком размещаются на диске backup-сервера перед упаковкой в Restic (нужно достаточно свободного места), нет гарантированной консистентности активных файлов, нет полной сохранности Windows ACL/xattr. Ссылки/специальные объекты для таких источников блокируют успешный статус, а не теряются незаметно. Отсутствуют ротация и безопасный сборщик мусора, независимая immutable-копия, автоматическое восстановление после уничтожения SQLite, приложения Windows/VSS/AD, Thunderbird, Dovecot, POP3/IMAP, 1С split-config. Не запускайте `restic forget/prune` вручную: это может повредить историю BackupHub.

## Установка Debian / Ubuntu (amd64)

Скачайте `.deb` и файл SHA256 из [предварительного релиза](https://github.com/mirivlad/BackupHub/releases/tag/v0.1.0-preview.1), проверьте сумму и установите:

```bash
sha256sum -c backuphub_0.1.0~preview.1_amd64.deb.sha256
sudo apt install ./backuphub_0.1.0~preview.1_amd64.deb
sudo runuser -u backuphub -- backuphub bootstrap -data-dir /var/lib/backuphub
```

Откройте `https://IP-сервера:8443/`, введите одноразовый токен из терминала, создайте администратора и войдите в систему. Установочный сертификат самоподписанный; замените его на доверенный или используйте проверенный reverse proxy с TLS. **Не публикуйте BackupHub прямо в Интернет до настройки HTTPS, сетевых ограничений и резервного копирования его собственных ключей.**

По умолчанию Restic-репозиторий находится на **том же сервере**, в `/var/lib/backuphub/repository`. Для защиты от потери диска **перед использованием** настройте отдельное хранилище и доступ к нему (см. [руководство по DEB](packaging/debian/README.md)) и сделайте независимую офлайн-копию `/var/lib/backuphub/master.key` и `restic.key`. Сохраните также состояние SQLite. Не перемещайте один только репозиторий, не сохранив ключи.

Веб-интерфейс: «Источники, история и восстановление». Добавьте источник, запустите задание, дождитесь успешного завершения в журнале, затем **скачайте и проверьте тестовый файл** из исторического снимка. Восстановление в исходный путь намеренно запрещено в Preview.

```bash
sudo systemctl status backuphub
sudo journalctl -u backuphub -n 100 --no-pager
```

## Разработка

Стек: Go 1.27, SQLite/WAL, Svelte 5/TypeScript, Restic, нативные сетевые коннекторы. Нет Bash-скриптов вместо P0-коннекторов или обязательных внешних брокеров.

```bash
go test -race ./...
npm ci --prefix web
npm run check --prefix web
npm run build --prefix web
go build -o backuphub ./cmd/backuphub
```

Автоматические GitHub Actions запускают Go/Svelte, реальное резервирование и восстановление через Restic, сборку и проверку установки Debian-пакета с запуском systemd и HTTPS API.
