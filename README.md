# BackupHub

[![Угостить разработчика кофе / Buy me a coffee](https://img.shields.io/badge/Support-Buy%20me%20a%20coffee-7055a5?style=flat-square&logo=buymeacoffee&logoColor=white)](https://mirv.top/support/)

**BackupHub** — свободная self-hosted система резервного копирования и восстановления. Лицензия GNU GPL-3.0-only.

## 0.7.0

**Восстановление после сбоев.** Задание сохраняет попытки в SQLite, автоматически повторяет временные ошибки и продолжает расписание после исчерпания лимита. Прерванную публикацию BackupHub сверяет с существующим манифестом Restic. [Правила повторов и испытания](docs/backup-resilience.md).

## Проверка и восстановление снимков

**Проверка новых снимков.** BackupHub сверяет пути, типы, размеры и назначения ссылок с деревом Restic через временный дисковый индекс. Restic проверяет данные при чтении. Снимок появляется в истории после проверки и записи переносимого манифеста.

**Обслуживание хранилищ.** В разделе «Хранилища» доступны ручная и плановая проверка метаданных либо всех данных. История показывает результат каждого запуска, дату, длительность и диагностику.

**Пробное восстановление.** Выберите файловый снимок в «Истории копий». Проверка восстанавливает автоматическую выборку либо обычные файлы по выбранному пути во временный каталог, сверяет размеры и SHA-256 и удаляет временные файлы. Результат хранится отдельно от проверки снимка при записи. Для PostgreSQL требуется отдельный тест восстановления приложения.

**Аварийное восстановление сервера.** Команды `backuphub recovery` сохраняют каталог и ключи, восстанавливают состояние на чистом сервере и импортируют более свежие снимки из сохранившихся Restic-репозиториев.

Версия 0.7.0 предназначена для предварительной эксплуатации. Для критичных серверов нужна проверенная независимая резервная копия.

Доступные типы источников:
- локальный каталог Linux (содержимое и базовые файловые метаданные);
- сетевая папка SMB с автоопределением версии. SMB2/3 имеют приоритет. Для устройств только с SMB1 требуются `smbclient`, NTLMv2 и подписывание;
- SSH/SFTP с паролем или приватным ключом OpenSSH либо PuTTY PPK. Для импорта PPK требуется `puttygen` из пакета `putty-tools`. Ключ сервера запоминается при первом подключении и проверяется при следующих;
- обычный PostgreSQL с логическим `pg_dump -Fc`;
- Postgres Pro для 1С с раздельным копированием `public.config`. Профиль проверен на стенде PostgreSQL 17. Совместимость со своей сборкой Postgres Pro и запуск информационной базы проверяйте на отдельном стенде.

Реализованы: ручной запуск, встроенный в задание графический cron-конструктор (минуты, часы, числа, месяцы, дни недели), простые интервалы и предпросмотр запусков, журнал выполнений и отказов, Restic-снимки файловых деревьев с необязательным паролем, история по датам, просмотр файлов, экспорт одного файла или выбранных папок и файлов в ZIP, безопасное восстановление в **новый** каталог на сервере. Web UI на русском, авторизация и аудит; один автономный экземпляр на площадку.

**Ограничения.** Удалённые деревья SMB/SFTP временно целиком размещаются на диске перед упаковкой в Restic. Консистентность открытых файлов и полная сохранность Windows ACL/xattr не гарантируются. Защищённая ротация, неизменяемая репликация, Windows/VSS/AD, Thunderbird, Dovecot и POP3/IMAP остаются в дорожной карте. Ручной запуск `restic forget/prune` может повредить историю BackupHub.

## Установка Debian / Ubuntu (amd64)

Скачайте `.deb` и файл SHA256 из [релиза v0.7.0](https://github.com/mirivlad/BackupHub/releases/tag/v0.7.0), проверьте сумму и установите:

```bash
sha256sum -c backuphub_0.7.0_amd64.deb.sha256
sudo apt install ./backuphub_0.7.0_amd64.deb
# Если интерактивная установка не создала администратора:
sudo runuser -u backuphub -- backuphub setup-admin -data-dir /var/lib/backuphub
```

Откройте `https://IP-сервера:8443/`, войдите с учётной записью администратора, созданной при интерактивной установке или через команду setup-admin. Установочный сертификат самоподписанный; замените его на доверенный или используйте проверенный reverse proxy с TLS. **Не публикуйте BackupHub прямо в Интернет до настройки HTTPS, сетевых ограничений и резервного копирования его собственных ключей.**

Существующий встроенный Restic-репозиторий для совместимости находится **на том же сервере**, в `/var/lib/backuphub/repository`. Для защиты от потери диска **перед использованием** выберите отдельный смонтированный том в веб-интерфейсе и назначьте его хранилищем задания (см. [несколько хранилищ и пикер](docs/multi-storage.md)). В отдельном разделе **«Настройки»** выбирается значение по умолчанию для новых репозиториев: с паролем либо без пароля. Этот режим можно изменить при добавлении конкретного хранилища. Оригинальный встроенный репозиторий всегда сохраняет прежний парольный режим.

Для аварийного восстановления сохраняйте [офлайн-комплект каталога и ключей](docs/recovery.md) отдельно от Restic-репозиториев. Для прямого чтения беспарольного архива нужны диск с репозиторием и Restic 0.17+. Такой архив может прочитать любой с доступом к диску.

Веб-интерфейс разделён на «Обзор», «Источники», «Хранилища», «Задания», «История копий», «Журнал выполнения», «Расписание и загрузка» и «Журнал службы». Добавьте источник, выберите или создайте хранилище, затем создайте задание. В его форме выберите периодичность, дату и время первого планового запуска и часовой пояс. Кнопка «Сохранить и запустить» сразу ставит задание в очередь. Запустите его, дождитесь результата и **проверьте экспорт тестового файла из исторического снимка**. Восстановление в исходный путь пока запрещено.

Источники и хранилища независимы. Каждое задание содержит собственную периодичность; общая сетка доступна в разделе «Расписание и загрузка».

Если после установки веб-интерфейс предлагает создание администратора, проверьте состояние каталога, с которым запускается сервис:

```bash
sudo runuser -u backuphub -- backuphub admin-status -data-dir /var/lib/backuphub
systemctl cat backuphub.service
```

Создание администратора через CLI (`setup-admin`) и через браузер (`bootstrap`) — **альтернативные** пути, а не два обязательных этапа. Минимальная длина пароля администратора — 8 Unicode-символов; для полноценной защиты рекомендуется более длинная уникальная парольная фраза. Не меняйте и не удаляйте `catalog.db` или `master.key` для решения проблем со входом.

```bash
sudo systemctl status backuphub
sudo journalctl -u backuphub -n 100 --no-pager
```

## Обновление до v0.7.0

1. Экспортируйте [офлайн-комплект восстановления](docs/recovery.md) и сохраните его отдельно от сервера.
2. Проверьте SHA256 нового пакета и установите его через `apt install`, как описано выше. Служба применит миграцию SQLite v15. Существующие снимки, подключения, расписания и ключи сохраняются. Задания получают три повтора с шагом 30 минут.
3. Убедитесь, что подключены прежние тома, и откройте «Проверки хранилища» для каждого репозитория. Плановые проверки изначально выключены. Выберите режим и интервал с учётом длительности полного чтения.
4. Запустите пробное восстановление хотя бы одного подходящего снимка и проверьте результат в истории. Процедуры диагностики и ограничения описаны в [руководстве по проверкам](docs/verification.md).

## Разработка

Стек: Go 1.27, SQLite/WAL, Svelte 5/TypeScript, Restic, нативные сетевые коннекторы. Нет Bash-скриптов вместо P0-коннекторов или обязательных внешних брокеров.

```bash
go test -race ./...
npm ci --prefix web
npm run check --prefix web
npm run build --prefix web
go build -o backuphub ./cmd/backuphub
```

Автоматические GitHub Actions запускают Go/Svelte, реальное резервирование и восстановление через Restic, сборку и проверку установки Debian-пакета с запуском systemd и HTTPS API.
