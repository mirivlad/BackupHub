# BackupHub

**BackupHub** — свободная self-hosted система резервного копирования и восстановления. Лицензия GNU GPL-3.0-only.

## 0.1.0 Preview 4

**Это устанавливаемая предварительная версия, не production-ready система.** Она позволяет попробовать основные файловые сценарии и восстановить собственные данные, но пока **не заменяет проверенную независимую резервную копию** критичных серверов.

Доступные типы источников:
- локальный каталог Linux (содержимое и базовые файловые метаданные);
- SMB2/3 (учётная запись, общая папка, подпапка; SMB1 не поддерживается);
- SSH/SFTP (пароль и проверка host key через `/etc/backuphub/known_hosts`);
- **обычный PostgreSQL** — логический `pg_dump -Fc` с проверкой TOC через `pg_restore -l`. **Специальный PostgreSQL Pro 1C с крупным `public.config` пока не поддерживается.**

Реализованы: ручной запуск, интервальное расписание, журнал выполнений и отказов, Restic-снимки файловых деревьев с необязательным паролем, история по датам, просмотр файлов, экспорт одного файла или выбранных папок и файлов в ZIP, безопасное восстановление в **новый** каталог на сервере. Web UI на русском, авторизация и аудит; один автономный экземпляр на площадку.

В Preview 4 добавлены вкладка **«Аварийное восстановление»**, экспорт Recovery Kit с целостной SQLite и ключами, подключение уцелевших Restic-дисков с восстановлением архивной истории по commit-маркерам без исходной SQLite и безопасная команда восстановления полного комплекта в новый каталог. Подробнее: [аварийное восстановление](docs/disaster-recovery.md). Комплект содержит секреты, должен храниться отдельно и не включает данные Restic.

**Ограничения:** удалённые деревья SMB/SFTP временно целиком размещаются на диске backup-сервера перед упаковкой в Restic (нужно достаточно свободного места), нет гарантированной консистентности активных файлов, нет полной сохранности Windows ACL/xattr. Ссылки/специальные объекты для таких источников блокируют успешный статус, а не теряются незаметно. Отсутствуют ротация и безопасный сборщик мусора, независимая immutable-копия, автоматическое восстановление рабочих конфигураций из Restic-маркеров, приложения Windows/VSS/AD, Thunderbird, Dovecot, POP3/IMAP, 1С split-config. Не запускайте `restic forget/prune` вручную: это может повредить историю BackupHub.

## Установка Debian / Ubuntu (amd64)

Скачайте `.deb` и файл SHA256 из [предварительного релиза](https://github.com/mirivlad/BackupHub/releases/tag/v0.1.0-preview.4), проверьте сумму и установите:

```bash
mv backuphub_0.1.0.preview.4_amd64.deb 'backuphub_0.1.0~preview.4_amd64.deb'
sha256sum -c backuphub_0.1.0.preview.4_amd64.deb.sha256
sudo apt install './backuphub_0.1.0~preview.4_amd64.deb'
sudo runuser -u backuphub -- backuphub setup-admin -data-dir /var/lib/backuphub
```

Откройте `https://IP-сервера:8443/`, войдите с учётной записью администратора, созданной при интерактивной установке или через команду setup-admin. Установочный сертификат самоподписанный; замените его на доверенный или используйте проверенный reverse proxy с TLS. **Не публикуйте BackupHub прямо в Интернет до настройки HTTPS, сетевых ограничений и резервного копирования его собственных ключей.**

Существующий встроенный Restic-репозиторий для совместимости находится **на том же сервере**, в `/var/lib/backuphub/repository`. Для защиты от потери диска **перед использованием** выберите отдельный смонтированный том в веб-интерфейсе и назначьте его хранилищем задания (см. [несколько хранилищ и пикер](docs/multi-storage.md)). В отдельном разделе **«Настройки»** выбирается значение по умолчанию для новых репозиториев: с паролем либо без пароля. Этот режим можно изменить при добавлении конкретного хранилища. Оригинальный встроенный репозиторий всегда сохраняет прежний парольный режим.

Для аварийного восстановления сохраняйте независимую офлайн-копию `/var/lib/backuphub/master.key`, `restic.key`, каталога SQLite и всех `restic-<id>.key` **для парольных хранилищ**. У беспарольных хранилищ файла `restic-<id>.key` нет — достаточно диска с репозиторием и Restic 0.17+. Любой с доступом к диску может читать беспарольный архив.

Веб-интерфейс: «Источники, история и восстановление». Добавьте источник, запустите задание, дождитесь успешного завершения в журнале, затем **скачайте и проверьте тестовый файл** из исторического снимка. Восстановление в исходный путь намеренно запрещено в Preview.

```bash
sudo systemctl status backuphub
sudo journalctl -u backuphub -n 100 --no-pager
```

## Разработка

Стек: Go 1.27, SQLite/WAL, Svelte 5/TypeScript, Restic, нативные сетевые коннекторы. Нет Bash-скриптов вместо P0-коннекторов или обязательных внешних брокеров.

```bash
go test -race ./...
npm ci --prefix web
npm run check --prefix web
npm run build --prefix web
go build -o backuphub ./cmd/backuphub
```

Автоматические GitHub Actions запускают Go/Svelte, реальное резервирование и восстановление через Restic, сборку и проверку установки Debian-пакета с запуском systemd и HTTPS API.
