# Проверка хранилищ и восстановления

## Состояния

- В «Истории копий» отображаются созданные и опубликованные снимки. «Проверка при записи» подтверждает, что BackupHub считал данные нового снимка и сверил их структуру с деревом Restic. Дисковый индекс хранится в каталоге состояния, его SQLite-кеш ограничен 4 МиБ. Большим деревьям нужно свободное место под индекс.
- В «Хранилищах» отдельно отображаются результаты проверки метаданных и полного чтения данных. Успешная проверка метаданных подтверждает согласованность структуры репозитория. Полная проверка дополнительно читает и проверяет packs с данными.
- «Пробное восстановление» относится к конкретному файловому снимку и хранилищу. Оно подтверждает восстановление выборки. Проверка запуска PostgreSQL, 1С и других приложений выполняется отдельно.
- «Не проверено», «В очереди», «Выполняется», «Прервано», «Ошибка» и «Проверка устарела» различаются в интерфейсе. Успех считается устаревшим через интервал своего режима проверки. Для ручного режима и пробного восстановления используется срок 30 дней. История сохраняет предыдущие запуски, включая успешные. Интерфейс показывает до 50 последних операций соответствующего вида.

## Хранилище

1. Откройте «Хранилища» → «Проверки хранилища» нужного репозитория.
2. Выберите «Метаданные» для обычного `restic check` или «Все данные» для `restic check --read-data`. Запустите проверку и откройте результат.
3. Для плановых запусков выберите режим, укажите интервал от 1 до 8760 часов и сохраните расписание. Значение 0 отключает расписание. Первый запуск наступает через выбранный период. Ручной запуск сохраняет дату следующей плановой операции. Пропущенные запуски объединяются в одну операцию.
4. Откройте «Подробности» при ошибке. Отключённый том нужно подключить повторно. При нехватке места освободите пространство на соответствующем томе, сохраняя данные и ключи Restic. При повреждении сохраните диагностику, определите затронутые данные и используйте независимую копию для восстановления.

Лимит времени составляет 30 минут для метаданных и 24 часа для полного чтения. Если Restic выводит количество обработанных packs, прогресс полного чтения виден в истории. В одном репозитории выполняется одна операция проверки или копирования BackupHub. Два независимых репозитория могут проверяться параллельно. Копирование ждёт освобождения своего репозитория без записей повторного ожидания. Другая копия может стартовать на свободном репозитории. Когда копирование уже просрочено, оно получает приоритет перед следующей проверкой того же репозитория. При штатном завершении службы активная проверка прерывается, а очередь сохраняется. После аварийной остановки служба помечает прерванные операции и убирает временные данные. При восстановлении офлайн-комплекта расписания ждут повторного сохранения, а перенесённая очередь закрывается со статусом «Прервано».

Restic использует собственные блокировки. Если блокировка сохраняется после закрытия процессов Restic, проверьте её владельца и все службы или хосты с доступом к репозиторию. После подтверждения, что репозиторий повсюду простаивает, администратор может запустить обычный `restic unlock` с учётными данными нужного репозитория и повторить проверку. BackupHub оставляет блокировки в покое, поскольку Restic может считать живой процесс устаревшим по одному только возрасту блокировки.

## Пробное восстановление

1. В «Истории копий» откройте снимок локального, SMB или SFTP-источника.
2. Запустите «Проверить выборку» или отметьте один файл либо папку и нажмите «Проверить выбранный путь». Без отметки кнопка проверяет текущую папку. Автовыборка берёт до 8 файлов из нескольких диапазонов размеров, общим объёмом до 256 МиБ. Для выбранного пути проверяются все обычные файлы в пределах 256 файлов и 2 ГиБ. При превышении лимита выберите меньший путь. Если непустые файлы превышают лимит автовыборки, история объясняет, почему она пропущена. Если обычные файлы только пустые, проба проверяет один из них.
3. BackupHub восстанавливает файлы в отдельный каталог внутри `/var/lib/backuphub/restore-checks` (для стандартной установки). Restic аутентифицирует данные по идентификаторам блоков из дерева снимка. BackupHub вычисляет SHA-256 этого потока и сравнивает его с SHA-256 файла, заново открытого с диска. Размеры сравниваются с метаданными снимка.
4. После проверки временные файлы удаляются. В результате остаются время, число и объём проверенных файлов или диагностика отказа.

Одновременно доступно одно пробное восстановление. Лимит времени составляет 10 минут. Для пробы нужно свободное место для выборки и ещё 32 МиБ. Символические ссылки, специальные файлы, права доступа и ACL в тестовую выборку не входят. Для полной проверки всех данных используйте режим «Все данные», а для проверки прикладной готовности разверните приложение на отдельном стенде.

## Замер индекса

```sh
BACKUPHUB_LARGE_TREE=1000000 go test ./internal/backup -run '^TestSnapshotIndexLargeTree$' -count=1 -v
```

Тест подаёт миллион записей и TAR в обратном порядке. В замере для v0.6.1 пиковая Go-куча составила 3,7 МиБ, пиковый RSS тестового процесса 46,5 МиБ. Замер включает индекс и разбор архива, дочерний Restic в нём не запускается. По умолчанию тест проверяет 100 тысяч записей.

## Известные ограничения

- **Высокий приоритет.** BackupHub ограничивает собственный индекс и читает TAR потоком. Потребление памяти дочерним Restic зависит от размера его индексов и отдельных деревьев. Каталог состояния требует свободного дискового места.
- **Средний приоритет.** Проверка целей ссылок читает отдельные объекты дерева Restic. Снимки с большим числом таких каталогов и байтовыми именами могут проверяться заметно дольше.
- **Средний приоритет.** В службе действует один исполнитель резервного копирования. Резервирование репозиториев уже выполняется до взятия задания. Увеличение числа исполнителей и проверка нагрузки планируются отдельно.
- **Средний приоритет.** Статус «Проба пройдена» относится к выбранным обычным файлам. Побайтовый тест ссылок, ACL и запуск приложений требуют отдельной процедуры. Имена, которые `restic ls --json` отдаёт неоднозначно, исключаются из автовыборки. Явная проба такого пути завершится с диагностикой.
