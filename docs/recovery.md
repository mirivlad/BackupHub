# Аварийный комплект BackupHub

Комплект сохраняет согласованную копию SQLite, ключ хранилища секретов и парольные файлы зарегистрированных Restic-хранилищ. Храните его отдельно от сервера BackupHub и носителей с резервными данными. Комплект содержит ключи в открытом виде. Защитите его шифрованием носителя и ограничьте доступ. Данные снимков остаются в самих Restic-репозиториях.

## Создание

Передайте путь к новому каталогу внутри приватного каталога на смонтированном носителе. Его родитель должен существовать и быть доступен пользователю `backuphub` для записи. Сервис может продолжать работу во время экспорта. Повторите экспорт после изменений ключей и конфигурации.

```sh
sudo runuser -u backuphub -- backuphub recovery export \
  -data-dir /var/lib/backuphub -kit /mnt/offline/backuphub-kit
```

Каталог публикуется целиком. Если указанный путь уже существует, команда завершится ошибкой. Используйте новое имя для следующей копии. Сохраняйте у каталога права `0700`, у файлов `0600`.

## На восстановительном сервере

1. Установите BackupHub и остановите сервис. Подключите сохранившиеся Restic-тома по путям из исходной конфигурации. Если `/var/lib/backuphub` уже существует, сохраните его под отдельным именем при остановленном сервисе. Сохраните содержимое вложенного `repository/`, если оно доступно.
2. Предоставьте пользователю `backuphub` доступ к комплекту и создайте восстановленное состояние по новому пути. Для штатного Debian-каталога родитель `/var/lib` требует прав администратора. В этом случае выполните команды ниже от имени администратора и перед запуском службы передайте файлы пользователю `backuphub`.

```sh
sudo backuphub recovery restore \
  -kit /mnt/offline/backuphub-kit -data-dir /var/lib/backuphub
sudo chown -R backuphub:backuphub /var/lib/backuphub
```

3. Верните вложенный Restic-репозиторий на исходный путь, если для встроенного хранилища использовался стандартный каталог. Импортируйте снимки, которые были записаны после экспорта комплекта.

```sh
sudo runuser -u backuphub -- backuphub recovery reconcile -data-dir /var/lib/backuphub
```

4. Запустите службу, войдите заново и проверьте восстановление нужной версии файла в новый каталог. Задания и плановые проверки после восстановления приостановлены. После проверки путей и источников включите задания и заново сохраните расписания проверок.

`reconcile` читает переносимые манифесты из зарегистрированных репозиториев. Операция выполняется отдельной транзакцией для каждого хранилища. Повторный запуск не дублирует историю. При возвращении томов по одному укажите `-repository-id ID`. Команда остановится на несоответствии репозитория каталогу, неоднозначном манифесте или недоступном снимке.

Для источника, добавленного после экспорта комплекта, импорт создаёт запись, из которой доступно восстановление. Чтобы снова создавать копии этого источника, укажите его подключение и учётные данные. Новые задания и секреты, добавленные после экспорта комплекта, потребуется настроить заново.

Команда проверяет SHA-256 файлов комплекта и целостность каталога перед публикацией. Для аварии, при которой сохранился только диск Restic, возможен прямой возврат файлов средствами Restic. Парольному репозиторию понадобится его парольный файл.
