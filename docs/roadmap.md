# Дорожная карта до BackupHub 1.0

Это этапы **разработки** полного продукта, не урезанные «скриптовые» релизы.

## A — Фундамент
- [x] Репозиторий, лицензия, спецификация и архитектурные границы.
- [x] Go-модуль, схема SQLite v1, `instance_uuid`.
- [x] Типизированные снимки и правила составного commit, модель состояний, retention dry-run.
- [x] Минимальный read-only health API; тесты и CI.
- [ ] Миграции/бэкап каталога и самостоятельный recovery kit.
- [ ] Vault/master key; первый администратор; сессии, роли и audit.
- [ ] Svelte/TypeScript UI с первичной настройкой.
- [ ] Scheduler, recoverable job runs и блокировки.
- [ ] Реальный адаптер Restic, переносимые манифесты, проверка восстановлением.

## B — Файловые источники
- [ ] SMB2/3, SSH/SFTP, изолированный SMB1; проверяемые гарантии метаданных.
- [ ] Исторические снимки, каталог/поиск по именам и исчезнувшим файлам.
- [ ] Retention/hold и отдельная обслуживающая операция.
- [ ] Экспорт файла, папки, произвольной выборки ZIP/TAR и полного снимка.
- [ ] Безопасный мастер восстановления в исходный/другой путь.

## C — Приложения
- [ ] Нативные логические бекапы PostgreSQL.
- [ ] Нативный PostgreSQL Pro 1C split-config, совместимость и стендовое восстановление.
- [ ] Windows WinRM/VSS, Thunderbird и AD System State.
- [ ] Dovecot/IMAP/ограниченный POP3 и восстановление ящиков.

## D — Доказательство надёжности
- [ ] Независимые репозитории/репликация и иммутабельность.
- [ ] Возврат данных после уничтожения BackupHub/SQLite.
- [ ] Периодические restore drills, нагрузочные/безопасностные тесты.
- [ ] Debian/systemd, Docker/Portainer, документация пользователей/админов.
- [ ] Все обязательные [AT-01–AT-25](specification-v0.1.md) на тестовых стендах.

**Правило выпуска:** отсутствие P0-коннектора не закрывается запуском старого скрипта. Для неподдержанных версий чётко указываются ограничения; 1.0 только после подтверждённых сценариев.
