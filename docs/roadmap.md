# Дорожная карта BackupHub до версии 1.0

Обновлено 10 ноября 2026 года. Статус соответствует выпущенной **v0.1.0-preview.3**. Планируется **Preview 4: аварийное восстановление**.

Принципы: полноценные встроенные коннекторы, никаких обязательных внешних скриптов в качестве ядра; одна автономная установка на площадку; независимое восстановление важнее отметки «копия выполнена».

## Реализовано (Preview 1–3)

- [x] Go-сервис, SQLite/WAL с миграциями до v6 и постоянным `instance_uuid`.
- [x] Первоначальная настройка администратора, вход/сессии, роли (базовая модель), CSRF, аудит, Vault.
- [x] Устанавливаемый DEB amd64, systemd и веб-интерфейс Svelte на русском.
- [x] Нативное файловое резервирование локального Linux, SMB2/3 и SSH/SFTP; обычный PostgreSQL через `pg_dump -Fc` (ограниченный профиль).
- [x] Интервальное расписание, запуск вручную, журнал задач и проверка данных Restic при создании.
- [x] История снимков, просмотр дерева, скачивание одиночных файлов и выбранных папок ZIP, восстановление в **новый** каталог.
- [x] Несколько локальных хранилищ, выбор места для задания, проверка реального mount, независимые Restic-репозитории.
- [x] Два режима Restic для **новых** хранилищ: с паролем или `--insecure-no-password`, настройка по умолчанию в отдельном разделе администратора. Старые репозитории не меняются.
- [x] Переносимые commit-маркеры Restic, достаточные для построения индекса завершённых снимков при аварии (самостоятельное восстановление каталога пока не реализовано).

## Следующий этап — Preview 4: восстановление после гибели сервера

- [ ] Администратор скачивает Recovery Kit: согласованный снимок SQLite, `master.key`, ключи **парольных** Restic-хранилищ, manifest с инструкцией.
- [ ] При потере SQLite новый экземпляр **подключает** существующий диск с Restic без автоматической инициализации и разрушительных операций.
- [ ] Восстановить историю из переносимых commit-маркеров только **завершённых** снимков, без ложного восстановления расписаний и паролей источников.
- [ ] Поддержка и парольного (с импортом оригинального ключа), и беспарольного архива.
- [ ] Повторный запуск импорта без дублирования истории; контроль коллизий, испорченных маркеров, чужих репозиториев.
- [ ] Проверка на отдельном чистом Linux/DEB: потеря сервера → диск → просмотр/ZIP/восстановление.
- [ ] Автономное восстановление полного комплекта конфигурации в выключенный сервис. Никакой замены работающей БД через HTTP.

## Preview 5 — безопасная ротация

- [ ] Политики ежедневных/недельных/месячных снимков, dry-run удаления, закреплённые снимки (hold).
- [ ] Независимая привилегированная операция `forget/prune`, блокировки от гонок с заданиями, защита последнего проверенного снимка.
- [ ] Тесты восстановления после ротации и при исчерпании места.

## Preview 6 — поиск и мастер восстановления

- [ ] Поиск файлов по имени/пути/датам, включая уже удалённые файлы.
- [ ] Сравнение снимков, большие экспорты и целый снимок.
- [ ] Восстановление на другой хост/на прежний хост с явным подтверждением, статусом и проверкой.
- [ ] Поддержка более полных Unix/SMB метаданных и безопасные ACL-сценарии.

## Последующие этапы до 1.0

- [ ] Специализированный нативный PostgreSQL Pro 1C, в т.ч. `public.config` и стендовый restore.
- [ ] Windows WinRM/VSS, Thunderbird, AD System State.
- [ ] Dovecot/IMAP, ограниченный POP3, восстановление почты.
- [ ] Изолированный SMB1, совместимость и fidelity-матрицы.
- [ ] Репликация на независимый носитель, неизменяемая копия, restore drills, уведомления, расписание/повторы.
- [ ] Полное управление пользователями/ролевыми полномочиями, hardening, Docker/Portainer, английский интерфейс.
- [ ] Приёмочные испытания AT-01–AT-25 на стендах.

**Не в ближайших релизах:** обычное открытое файловое хранилище (без Restic), обзор нескольких BackupHub на одной панели, пользовательские сценарии на скриптах как расширение. Ни одна из этих функций не подменяет обязательные P0-коннекторы.
