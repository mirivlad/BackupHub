# Первичная безопасность BackupHub (этап A)

**Важное ограничение:** пока готовы только безопасное локальное хранение секретов и API аутентификации. Коннекторы, планировщик и веб-интерфейс ещё разрабатываются. Нельзя использовать эту сборку в качестве системы резервного копирования.

## 1. Установка на тестовом сервере

Go 1.23+:

```bash
go build -o backuphub ./cmd/backuphub
mkdir -m 0700 -p /tmp/backuphub-demo
./backuphub init -data-dir /tmp/backuphub-demo
./backuphub bootstrap -data-dir /tmp/backuphub-demo
./backuphub serve -data-dir /tmp/backuphub-demo -listen 127.0.0.1:8085
```

`bootstrap` выводит **одноразовый** секрет на 20 минут только в терминал администратора. Его нужно сохранить временно и убрать после создания учётной записи. Повторный bootstrap после создания первого администратора невозможен.

Каталог `catalog.db` хранит только хеши токенов сессий и Argon2id-паролей. Секреты будущих SMB/SSH/IMAP/SQL-подключений будут шифроваться AES-256-GCM в `vault_secrets`; файл `master.key` с правами 0600 хранится отдельно от SQLite. **Не удалять и не перегенерировать master.key!** Потеря ключа делает шифрованные секреты невосстановимыми. Требуется офлайн-копия с ограниченным доступом.

## 2. API первичной настройки

До подключения настоящего UI доступен API. Для локальной проверки без HTTPS использовать `curl` на том же хосте. К удалённым клиентам подключаться только через настроенный TLS reverse proxy (например, Nginx), выставляющий HTTPS. Backend слушает только loopback.

```bash
curl -s http://127.0.0.1:8085/api/v1/setup/status
# Заполните bootstrap_token значением команды backuphub bootstrap:
curl -X POST http://127.0.0.1:8085/api/v1/setup/admin \
  -H 'Content-Type: application/json' \
  --data '{"bootstrap_token":"PASTE_TOKEN","username":"admin","password":"YOUR-STRONG-PASSPHRASE"}'
```

Пароль — минимум 12 байт, хранится с Argon2id. Не копируйте реальный пароль в shell history; лучше передавать JSON из локального файла с правами 0600 или из stdin.

### Сессии

`POST /api/v1/auth/login` — JSON `username`, `password`; при успехе возвращает Secure, HttpOnly, SameSite=Strict cookie сессии и Secure CSRF cookie. Срок действия сессии — 7 дней, без скрытого продления. `GET /api/v1/auth/me` возвращает пользователя; `POST /api/v1/auth/logout` требует cookie + заголовок `X-BackupHub-CSRF` со значением из CSRF cookie. `GET /api/v1/audit` доступен администраторам и аудиторам, но обычным пользователям — нет. `GET /api/v1/system/identity` требует авторизации.

HTTP-only loopback предназначен для тестов/локальной связки с TLS reverse proxy. Secure cookies не рассчитаны на обычный браузерный HTTP-доступ. **Не публикуйте этот порт напрямую** и не подключайте его к недоверенному reverse proxy.

## 3. Границы реализованного

- Готово: Argon2id, bootstrap с истечением срока, запрет повторного создания админа, сессии/отзыв, CSRF, заголовки защиты, rate limit, аудит базовых событий, AES-256-GCM хранилище, SQLite v2.
- Не готово: серверные ACL на всех API, пользовательский интерфейс, каталог снимков/restore, аварийный recovery kit, секреты при экспорте, автоматизированное управление всеми ролями.
- Vault не спасает от компрометации ОС backup-сервера, если злоумышленник имеет доступ и к базе, и к master.key. Защищённая внешняя копия и разграничение привилегий обязательны.

## 4. Тесты

`go test -race ./...` проверяет правильный и неправильный bootstrap, пароль, сессии/logout/CSRF, запреты доступа, порчу ciphertext, потерю ключа и проверки разрешений. Тесты работоспособности ещё **не** являются тестами восстановления реальных данных.
