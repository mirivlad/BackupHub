# BackupHub v0.2.1 — расписание внутри задания

Теперь создание резервного копирования — одна операция: **источник → хранилище → периодичность → сохранить**. Отдельный экран «Расписания» и его API удалены.

## Изменения

- В форме «Новое задание» задаются источник, хранилище и периодичность: каждый день, по выбранным дням недели или через N минут, часов или дней.
- Обязательно указываются **дата, время и часовой пояс первого планового запуска**. Интервал «каждые 7 дней» отсчитывается от этой даты, а не от создания задания или завершения предыдущего копирования.
- Интервалы в днях используют календарные даты в указанном часовом поясе, сохраняя местное время при переходе на летнее и зимнее время. Минуты и часы — реальные интервалы времени.
- **«Сохранить и запустить»** атомарно создаёт задание и немедленно ставит его в очередь; **«Сохранить задание»** создаёт только расписание.
- У существующих заданий есть кнопка **«Запустить сейчас»**. Ручной запуск не сдвигает плановое время следующего копирования.
- Расписание теперь принадлежит заданию и не существует как отдельная пользовательская сущность.
- Миграция SQLite v8 сохраняет учётные записи, источники, ключи, существующие задания и снимки.

## Установка и обновление

Загрузите пакет и SHA256 со страницы https://github.com/mirivlad/BackupHub/releases/tag/v0.2.1

```bash
sha256sum -c backuphub_0.2.1_amd64.deb.sha256
sudo apt install ./backuphub_0.2.1_amd64.deb
```

При обновлении версии 0.2.0 каталог /var/lib/backuphub удалять **не нужно**. Если в 0.2.0 было создано отдельное, ещё не использованное расписание, оно просто перестанет отображаться. Привязанные к заданиям расписания сохраняются.

BackupHub пока не заменяет проверенную систему резервирования критичных данных. Храните ключи независимо от сервера и регулярно проверяйте восстановление.
