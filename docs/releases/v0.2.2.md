# BackupHub v0.2.2 — гибкое расписание, редактирование и SSH

**При создании задания копирование больше не запускается автоматически.** Нажмите «Запустить сейчас» непосредственно в списке заданий.

- Графический cron-конструктор: минуты, часы, числа месяца, месяцы и дни недели. Предпросмотр пяти ближайших запусков рассчитывает серверный планировщик. Интервалы и календарные правила сохранены.
- Источники и задания можно редактировать без пересоздания: ID и история резервных копий сохраняются. Во время выполнения задания изменение блокируется.
- Для локальных источников видны статусы доступа, а журнал различает отсутствие каталога и недостаток прав.
- Служба работает под пользователем `backuphub`, но с ограниченной capability `CAP_DAC_READ_SEARCH` для **чтения** закрытых каталогов. `ProtectHome=read-only`, `ProtectSystem=strict`; глобальная запись в `/home` и системные каталоги запрещена.
- SSH/SFTP: **логин и пароль** остаются доступными и обратно совместимыми, в том числе после редактирования старого источника. Дополнительно можно загрузить OpenSSH приватный ключ и указать парольную фразу в UI.
- Ключ SSH-сервера автоматически сохраняется при первом соединении (TOFU). Его SHA-256-отпечаток виден в списке источников; изменение ключа блокирует подключение. При первом соединении возможна MITM-подмена, поэтому отпечаток следует сверить независимым способом.
- Приватные ключи, пароли и парольные фразы хранятся в зашифрованном хранилище BackupHub. Они не отдаются через API списка источников.
- Каталог SQLite обновляется до схемы v10 с сохранением источников, паролей, ключей, истории и учётных записей.

## Установка и обновление

Скачайте с [GitHub Releases](https://github.com/mirivlad/BackupHub/releases/tag/v0.2.2) Debian-пакет и файл SHA-256 в одну папку:

```bash
sha256sum -c backuphub_0.2.2_amd64.deb.sha256
sudo apt install ./backuphub_0.2.2_amd64.deb
```

При обновлении **не удаляйте `/var/lib/backuphub`**. Там хранятся база, зашифрованные учётные данные и ключи восстановления.

Версия всё ещё не предназначена для единственного критического резервирования без проверенного восстановления и независимого хранения копий.
