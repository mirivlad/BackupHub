# BackupHub v0.1.0 Preview 3 — Restic без пароля и системные настройки

Третья предварительная версия добавляет выбор режима защиты для **новых**
Restic-хранилищ, отдельный экран «Настройки» и независимое восстановление
беспарольного архива стандартным Restic после потери сервера BackupHub.

## Что изменилось

- В боковой панели веб-интерфейса для администратора появился самостоятельный
  раздел **«Настройки»**. В нём выбирается режим новых хранилищ по умолчанию:
  **«С паролем»** либо **«Без пароля»**.
- В форме создания хранилища такой же простой выбор: системный режим уже
  подставлен, но для конкретного нового диска его можно изменить.
- Restic с паролем по-прежнему использует отдельный случайный секретный ключ
  на каждый репозиторий; соответствующие файлы находятся в
  `/var/lib/backuphub/restic-<id>.key`.
- Restic без пароля инициализируется через `--insecure-no-password`.
  **Файл ключа для такого репозитория не создаётся**, и каждый последующий
  вызов Restic (снимки, проверка, просмотр, экспорт, восстановление) получает
  тот же флаг автоматически.
- Режим фиксируется **при создании** репозитория. Не происходит скрытой
  конвертации старых архивов, смены пароля или удаления ранее созданных
  секретов. Новая системная настройка влияет только на новые хранилища.
- SQLite v5 → v6: старым хранилищам присваивается прежний режим
  `password`, значение системного параметра при обновлении тоже
  `password`. При чтении неизвестного режима используется отказ, а не
  переключение на беспарольный.
- Защищённые исходные данные (пароли SMB/SFTP/PostgreSQL) продолжают
  храниться в Vault с `master.key` независимо от способа защиты Restic.

## Аварийное восстановление без ключа и без BackupHub

Если диск со снимками выжил, но сам BackupHub и его SQLite потеряны,
подключите и смонтируйте диск на любом Linux. Потребуется Restic **0.17+**.

```bash
sudo apt install restic

# Показать все снимки, включая служебные манифесты
restic --repo /mnt/disk1/BackupHub/repository --insecure-no-password snapshots

# Показать снимки файлов (служебные снимки имеют другие теги)
restic --repo /mnt/disk1/BackupHub/repository --insecure-no-password snapshots --tag bh-pending

# Восстановить конкретный ID настоящего снимка файлов
restic --repo /mnt/disk1/BackupHub/repository --insecure-no-password restore SNAPSHOT_ID --target /tmp/restored
```

В этом режиме не нужен ни пароль, ни `restic-<id>.key`, ни `master.key`,
ни каталог SQLite. При этом **Restic по-прежнему хранит данные в собственном
формате**, а не в виде открытых папок. Данные по-прежнему шифруются
технически, но открываются с общедоступным пустым паролем.
Любой, кто получил доступ к диску или его полной копии, может их прочесть.

## Установка или обновление

Загрузите DEB и файл SHA256 со страницы релиза, затем:

```bash
mv backuphub_0.1.0.preview.3_amd64.deb 'backuphub_0.1.0~preview.3_amd64.deb'
sha256sum -c backuphub_0.1.0.preview.3_amd64.deb.sha256
sudo apt install './backuphub_0.1.0~preview.3_amd64.deb'
```

Откройте `https://IP-сервера:8443/`, войдите администратором, выберите
«Настройки» → режим новых архивов. Уже созданные архивы продолжат
работать с первоначальными ключами.

**Ограничения Preview:** не production-ready, нет надёжной автоматической
ротации и независимых immutable-реплик, нет специальных коннекторов AD/VSS,
PostgreSQL Pro 1C и почты. Требуется регулярно проверять восстановление
и хранить копии ключей от *парольных* архивов независимо от сервера.
