# BackupHub v0.1.0 Preview 4 — восстановление после гибели сервера

Новый этап посвящён возвращению истории копий и конфигурации, когда предыдущий сервер BackupHub перестал существовать.

## Новое

- Отдельная вкладка администратора **«Аварийное восстановление»**.
- **Recovery Kit** — скачать ZIP с согласованной резервной копией SQLite и ключами всех зарегистрированных парольных репозиториев. Выгрузка по авторизованному HTTPS и с аудитом.
- **Подключить существующий архив** — выбрать смонтированный диск и прежнюю папку с `repository/config`, указать защиту и, если архив парольный, содержимое оригинального файла ключа.
- **Восстановить историю без SQLite** — BackupHub прочитает commit-маркеры внутри Restic, проверит ссылки на настоящие снимки файлов и восстановит архивный индекс. Незавершённые снимки не импортируются.
- По окончании доступны прежние даты, просмотр файлов, скачивание отдельных файлов/ZIP и восстановление в новый каталог. Исходные рабочие задания из маркеров не восстанавливаются.
- **Офлайн-команда восстановления комплекта** `backuphub recovery-kit-restore -kit ... -data-dir NEW_EMPTY_DIRECTORY` — проверяет ZIP, сверяет SQLite и категорически запрещает перезапись существующего каталога.
- **Degraded recovery mode** — при наличии каталога прошлой установки, но отсутствии старого репозитория `primary`, BackupHub не пересоздаёт его молча. Сохранившиеся внешние хранилища остаются доступными.

## Установка

```bash
mv backuphub_0.1.0.preview.4_amd64.deb 'backuphub_0.1.0~preview.4_amd64.deb'
sha256sum -c backuphub_0.1.0.preview.4_amd64.deb.sha256
sudo apt install './backuphub_0.1.0~preview.4_amd64.deb'
```

Существующие ключи, хранилища и задания при обновлении сохраняются. Схема каталога v6 (без новых миграций). Обычные BackupHub-инстансы продолжают работать как раньше.

## Что обязательно помнить

Сам Recovery Kit **содержит секреты** и не зашифрован дополнительным паролем. Его следует сохранять на отдельном защищённом носителе. В него **не входят данные больших Restic-репозиториев** — сами backup-диски необходимо сохранять отдельно.

При импорте из диска пользователь `backuphub` должен иметь доступ к существующему приватному каталогу; helper не меняет права уже существующих папок. Для passwordless Restic используется `--insecure-no-password`; для защищённого архива нужен настоящий `restic-<id>.key` / `restic.key`.

**Полная инструкция**: [docs/disaster-recovery.md](../disaster-recovery.md).

## Известные ограничения

Предварительный выпуск, не production-ready. Импортированная только из Restic история не восстанавливает пароли SMB/SFTP/БД, живые задания и интервалы расписания. Настраивать источники повторно необходимо вручную. Retention, независимые immutable-копии, восстановление ACL/VSS и специфической 1С ещё не реализованы.
