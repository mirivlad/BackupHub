# BackupHub v0.1.0 Preview 2 — установка и несколько хранилищ

Второй предварительный выпуск: установка Debian/Ubuntu amd64, опциональное
интерактивное создание первого администратора и несколько отдельных локальных
Restic-хранилищ, выбираемых для каждого источника через веб-интерфейс.

## Изменения с Preview 1

- `sudo apt install ./backuphub_0.1.0~preview.2_amd64.deb` создаёт системного
  пользователя `backuphub`, HTTPS-сервис и безопасный systemd Unix-socket для
  подготовки каталогов. При интерактивном запуске установщик предлагает сразу
  задать логин и пароль администратора, без передачи пароля в аргументах, файлах
  debconf и логах.
- При установке без терминала или отказе от ввода пароль можно задать позднее:
  ```bash
  sudo runuser -u backuphub -- backuphub setup-admin -data-dir /var/lib/backuphub
  ```
  Существующий механизм одноразового bootstrap-токена также сохранён.
- Веб-интерфейс: список смонтированных томов, навигация по каталогам, создание новой папки для BackupHub или выбор существующей директории, уже принадлежащей backuphub с режимом 0700; отображение доступного места.
- Каждый новый репозиторий хранит собственные зашифрованные данные Restic,
  а ключи `restic-<id>.key` остаются в защищённом служебном каталоге.
- Назначение репозитория задаётся для каждого источника и меняется отдельно.
  Все ранее созданные снимки остаются в том репозитории, где они созданы;
  история, ZIP-экспорт и восстановление автоматически используют правильный диск.
- Миграция каталога SQLite v4→v5 сохраняет действующие задания и привязывает
  их к прежнему репозиторию `primary`. Настройки `BACKUPHUB_REPOSITORY`
  для прежнего репозитория не переносятся и не подменяются.
- При исчезновении диска репозиторий не пересоздаётся автоматически на
  системном разделе. Новое назначение нельзя выбрать во время активной операции.

## Установка и обновление

Скачайте оба файла из Assets на странице релиза, затем проверьте SHA256:

```bash
mv backuphub_0.1.0.preview.2_amd64.deb 'backuphub_0.1.0~preview.2_amd64.deb'
sha256sum -c backuphub_0.1.0.preview.2_amd64.deb.sha256
sudo apt install './backuphub_0.1.0~preview.2_amd64.deb'
```

Откройте `https://<сервер>:8443/`. Если администратор ещё не создан,
запустите безопасный интерактивный `setup-admin` или bootstrap.

**Примеры:** подключите диск в `/mnt/disk1` и второй в `/backup2`.
Откройте «Хранилища», выберите первый том и создайте папку
`BackupHub-Office`, затем второй и `BackupHub-Postgres`.
При настройке каждого источника выберите свой диск.

Выбирать можно только реально смонтированные носители внутри
`/mnt`, `/media`, `/backup`, `/backup2`, `/srv/backups`;
неподключённые и системные папки намеренно скрыты. Помощник не
переустанавливает владельцев существующих каталогов и не имеет
API удаления файлов. Для сетевых томов со специфическими правами
(NFS root-squash, CIFS) требуется убедиться, что файловая система позволяет
создать папку, доступную непривилегированному `backuphub`.

## Ограничения безопасности и готовности

Это **Preview, не релиз 1.0**. Список источников и ограничений Preview 1
по-прежнему актуален. Нет PostgreSQL Pro 1C split-config, VSS/AD, полноценных
ACL для SMB, обязательного автоматического restore-drill, безопасного retention
или независимой immutable-репликации. Отказ диска с единственной резервной
копией всё ещё приводит к потере данных; используйте отдельные физические
носители или реплику в независимой системе. Нельзя удалять Restic-снимки
через `restic forget/prune` вручную.

Подробности модели безопасности и пользовательского сценария:
[docs/multi-storage.md](../multi-storage.md).
